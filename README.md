# Портфолио: аналитика данных

Четыре рабочих артефакта, которые показывают не «я умею в аналитику», а
конкретные вещи: построить дашборд, разобрать эксперимент, собрать пайплайн,
вытащить данные с сайта и отдать их в чистом виде.

Всё воспроизводится локально, без облаков и платных сервисов.

## Как посмотреть за две минуты

1. `01-dashboard/dashboard.html` — открыть в браузере. Живые фильтры по периоду
   и категории, экспорт в CSV, без интернета.
2. `02-ab-test/report.html` — открыть в браузере. Весь разбор эксперимента на
   одной странице, с выводами.
3. `03-airflow-dag/README.md` — схема пайплайна и список решений.
   `python run_tests.py` — 43 проверки.
4. `04-parser/` — `python main.py`, на выходе `out/books.xlsx` с листом
   «Сводка».

## Что важно понимать про данные

- **Дашборд и A/B-тест — на синтетике.** Структура повторяет реальные кейсы,
  значения сгенерированы с фиксированным seed. Это указано и в самих файлах:
  выдавать чужую выручку за свою — плохая стратегия, проверяется на первом же
  собеседовании. Зато **вся методология настоящая**: числа на странице A/B-теста
  посчитаны scipy, а не вписаны руками.
- **Парсер работает на живом сайте**, просто на публичном полигоне
  `books.toscrape.com` — чтобы не парсить чужие маркетплейсы и не нарушать ToS.
- **Airflow-пайплайн проверен статически и юнит-тестами**, живой прогон в
  Airflow требует Docker (команда в README).

## Про качество, а не про объём

В каждом проекте заложены вещи, которые отличают рабочую аналитику от учебной:

- **идемпотентность** — повторный запуск не задваивает данные;
- **гейты качества** — пайплайн падает на плохих данных, а не публикует их;
- **честные пропуски** — неизвестное остаётся `None`, а не превращается в ноль;
- **проверка допущений** — SRM, расчёт мощности, поправка на множественные
  сравнения;
- **разделение транспорта и разбора** — парсер не зависит от сети в тестах.

## Формулировки для резюме

> Собрал портфолио из четырёх проектов: BI-дашборд на 96 SKU и 180 дней
> (self-contained HTML, без внешних библиотек), разбор A/B-теста на 300 000
> сессий с проверкой SRM и расчётом мощности, ETL-пайплайн на Airflow с
> идемпотентной загрузкой и гейтами качества (43 автотеста), парсер с
> нормализацией и выгрузкой в Excel (21 автотест).

> В разборе A/B-теста показал кейс, где значимый рост конверсии (+8%) не дал
> роста прибыли: субсидия доставки выросла на 51% и съела эффект. Решение —
> не раскатывать в текущем виде.

## Запуск всего подряд

```bash
cd 01-dashboard && PYTHONIOENCODING=utf-8 python build.py
cd ../02-ab-test && PYTHONIOENCODING=utf-8 python build.py
cd ../03-airflow-dag && python run_tests.py
cd ../04-parser && python tests/test_parser.py
```

Нужен Python 3.11+ с `pandas`, `scipy`, `numpy`, `beautifulsoup4`, `openpyxl`,
`requests`. Для браузерного бэкенда парсера — ещё Node.js и Playwright.
