# 05 · On-chain аналитика: стейблкоины и DeFi TVL

Дашборд, который отвечает на вопрос «сколько денег в крипте и где они лежат» — по публичным
данным, без биржевых API и без ключей.

**Открыть:** [`dashboard.html`](dashboard.html) — один файл, без интернета и без CDN.

Снимок на 2026-11-21: стейблкоинов в обращении **282.53B $**, DeFi TVL **422.61B $**,
топ-10 протоколов держат **55%** всего TVL, HHI **775** (рынок раздробленный).

---

## Зачем этот артефакт

Три вещи, которые проверяются на собеседовании и которые здесь видны в коде, а не на словах:

1. **Слойность.** Сырой снимок → SQLite → SQL-запросы → дашборд. Цифры на экране — результат
   запросов из `queries/`, а не заранее посчитанные константы. Любую метрику можно пересчитать
   и показать, откуда она взялась.
2. **Внимание к определениям.** TVL протокола считается по всем сетям сразу, поэтому сумма по
   категориям ≠ сумма по сетям. Стейблкоины берутся только USD-pegged. Эти оговорки выписаны в
   футере дашборда, а не спрятаны.
3. **Воспроизводимость.** `node bin/fetch.mjs` обновляет снимок, `python build.py` пересобирает
   всё офлайн, `python run_tests.py` проверяет расчёты. Один и тот же вход даёт один и тот же выход.

## Источник данных

Публичный API [DefiLlama](https://defillama.com/docs/api) — четыре эндпоинта, без ключа:

| Файл в `data/` | Эндпоинт | Что внутри |
|---|---|---|
| `stablecoins_all.json` | `stablecoincharts/all` | дневной ряд капитализации всех стейблкоинов |
| `stablecoins_list.json` | `stablecoins` | состав рынка по монетам |
| `chains.json` | `v2/chains` | TVL по 426 сетям |
| `protocols.json` | `protocols` | 9 086 протоколов с динамикой 1d/7d и списком сетей |

Ловушка, на которой легко ошибиться: `stablecoincharts/all?stablecoin=1` отдаёт **только USDT**
(174B), а без параметра — весь рынок (282B). В `bin/fetch.mjs` это закомментировано на месте.

## Запуск

```bash
node bin/fetch.mjs        # обновить снимок в data/ (нужна сеть)
python build.py           # посчитать и собрать dashboard.html (сеть не нужна)
python run_tests.py       # 23 теста расчётов, без сети и без БД
```

Зависимостей нет вовсе: только стандартная библиотека Python и встроенный `fetch` в Node ≥ 18.
Ни pandas, ни matplotlib, ни JS-фреймворков — графики нарисованы SVG вручную, чтобы файл
открывался двойным щелчком у любого, у кого нет интернета.

## Структура

```
05-onchain/
├── bin/fetch.mjs          скачивание снимка
├── build.py               сборка: JSON → SQLite → SQL → HTML
├── queries/               SQL, который считает цифры
│   ├── chains_top.sql     топ сетей + доля
│   ├── categories.sql     агрегация по категориям протоколов
│   ├── protocols_top.sql  топ протоколов
│   ├── movers.sql         сильнейшие движения недели
│   └── stablecoin_latest.sql  последняя точка ряда
├── src/metrics.py         чистые функции: HHI, доли, проценты, форматирование
├── tests/test_metrics.py  23 теста
├── template.html          вёрстка дашборда (плейсхолдер __DATA__)
├── dashboard.html         результат сборки
└── out/                   payload.json, CSV-выгрузки, onchain.db
```

## Что считается и как проверено

| Метрика | Формула / правило | Проверка |
|---|---|---|
| Изменение за N дней | `(new - old) / old`, база — ближайший день не позже `сегодня - N` | `nearest_before_index`, 4 теста |
| HHI | сумма квадратов долей в процентах (0…10000) | 5 тестов, включая монополию = 10000 |
| Доля топ-N | сумма N крупнейших / общая сумма | 3 теста |
| Формат сумм | 1.23T / 456.7B / 12.3M | 3 теста |

Отдельно исправлено: при нулевой базе `pct_change` возвращает `None`, а не `inf` — иначе на
графике появляется бесконечность и подпись `NaN`.

## Чего здесь нет (и это не забыто)

- **Адресных метрик** — сколько уникальных кошельков в протоколе, сколько транзакций. Это требует
  индексатора (Dune, Flipside) или своего нод-доступа; в агрегаторе таких данных нет.
- **Потоков по дням в разрезе сети** — только срез TVL, без притока/оттока за день.
- **Сравнения год к году по каждой сети** — сейчас есть только по общей массе стейблкоинов.

Следующий шаг, если понадобится: переписать `queries/*.sql` под Dune и посчитать по логам
блокчейна, а не по агрегатору. Схема слоёв это позволяет — меняются только SQL-файлы.
