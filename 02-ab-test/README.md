# A/B-тест: снижение порога бесплатной доставки

Полный разбор эксперимента: дизайн, расчёт мощности, проверка SRM, тест
первичной метрики, guardrail-метрики, разбор механизма, сегменты и решение
по раскатке.

Открыть: `report.html` — самодостаточная страница, работает офлайн.

## Кейс

Маркетплейс снижает порог бесплатной доставки с **3 000 ₽ до 2 000 ₽**.

Гипотеза: часть клиентов с дешёвыми корзинами, которым доставка стоит 250 ₽,
перестанет уходить из корзины — конверсия вырастет.

Проверено на **300 000 сессий** за 14 дней, деление 50/50.

## Результат

| Метрика | Контроль | Тест | Δ | p |
|---|---|---|---|---|
| Конверсия в заказ | 3,17% | 3,43% | **+8,1%** | 8·10⁻⁵ |
| Выручка на сессию | 123,66 ₽ | 131,14 ₽ | **+6,1%** | 0,024 |
| Средний чек | 3 899,87 ₽ | 3 826,04 ₽ | −1,9% | 0,26 |
| Субсидия доставки | 3,95 ₽ | 5,94 ₽ | **+50,6%** | 10⁻⁵⁵ |
| Чистая маржа на сессию | 28,63 ₽ | 28,50 ₽ | **−0,4%** | 0,87 |

**Вывод: раскатывать нельзя.** Конверсия и выручка выросли статистически
надёжно, но субсидия доставки выросла на 50,6% и съела весь прирост прибыли.
Чистая маржа изменилась на −0,13 ₽ с интервалом [−1,66; +1,40] — данных
не хватает даже на то, чтобы утверждать, что она не упала.

Это главный смысл кейса: **тест, остановленный на первой значимой метрике,
дал бы неправильное решение «катим»**.

## Метод

- Двухвыборочный z-тест для долей (конверсия, возвраты), Welch t-test для средних.
- **SRM-проверка** через χ²: p = 0,70 — деление трафика корректное.
- **Расчёт мощности** до старта: для эффекта +5% относительно нужно 193 131
  сессия на плечо; набрано ~150 000 на плечо, MDE = ±5,7%.
- **Поправка на множественные сравнения** (Бонферрони) в разбивке по сегментам:
  7 сегментов, без поправки значимы 6, с поправкой — 4.
- Разложение Δ прибыли на компоненты: маржа от выручки, субсидия, возвраты.

## Что ограничивает выводы

14 дней — короткий горизонт для возвратов и отмен, которые дозревают 2–4 недели.
Эффект новизны не отделён. Товарная маржа взята константой 27% — в реальности
дешёвые корзины часто менее маржинальны, и тогда вывод только усиливается.

## Запуск

```bash
PYTHONIOENCODING=utf-8 python build.py
```

Скрипт считает всё заново и пересобирает `report.html`, `results.json` и
`data/*.csv`. Все числа на странице вычислены из данных — ни одно не вписано
руками. Seed фиксирован, поэтому результат воспроизводится один в один.

Данные синтетические: механика «эффект сильнее на малых корзинах» задана
явно, дальше всё считается честной статистикой.
