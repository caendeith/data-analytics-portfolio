# Парсер каталога → чистая таблица

Сбор данных с сайта, нормализация, проверки качества и выгрузка в CSV + Excel
одной командой. Именно в таком виде это продаётся заказчику: не «скрипт»,
а файл, который можно открыть и использовать.

```bash
python main.py                          # 5 страниц каталога = 100 книг
python main.py --max-pages 50           # весь каталог = 1000 книг
python main.py --backend browser        # если HTTP режется прокси
```

Результат в `out/books.xlsx` — два листа: **Данные** (плоская таблица с
фильтрами и закреплённой шапкой) и **Сводка** (ключевые цифры, отчёт о качестве,
разрез по категориям).

## Почему books.toscrape.com

Это публичный полигон, специально сделанный для отработки скрейпинга.
Показывать в портфолио парсер чужого маркетплейса — плохая идея: нарушение
ToS, риск блокировки и вопрос «а вы вообще законопослушны?». Здесь тот же
набор задач (пагинация, карточки, нормализация цен, дедупликация) без
юридических рисков.

## Архитектура: сбор и разбор разделены кешем

```
bin/fetch.mjs (Playwright)  ──┐
src/fetcher.py (requests)   ──┴──►  data/cache/<sha1>.html  ──►  src/parser.py (bs4)
                                                                    │
                                              src/cleaner.py ◄──────┘
                                                   │
                                    out/books.xlsx, data/books_clean.csv
```

Кеш — это контракт между этапами:

- **парсер вообще не ходит в сеть** — читает готовый HTML, поэтому тесты
  работают офлайн, а повторный запуск бесплатен;
- **прерванный сбор продолжается**, а не начинается заново: результаты
  дописываются в `data/raw.jsonl` построчно;
- **два транспорта**: `requests` по умолчанию (для статики браузер не нужен —
  это в разы быстрее), Playwright как резерв, когда данные рисуются JS или
  трафик идёт только через браузер.

## Нормализация и качество

Парсер достаёт `£51.77` и `In stock (22 available)` — но отдавать такое
заказчику нельзя. Поэтому:

- цена → `float`, остаток → `int`, рейтинг → `1..5`;
- **ненайденное остаётся `None`, а не нулём**: ноль исказит средние и спрячет
  проблему;
- дедупликация по `UPC` (не по названию — названия повторяются легально);
- 11 проверок качества перед выгрузкой: строки есть, колонки на месте, `UPC`
  заполнен и уникален, цены разобраны и в коридоре, рейтинг валиден, остаток
  не отрицательный, категория заполнена. Провал любой проверки → код возврата 2
  и пометка в отчёте.

## Тесты

```bash
python tests/test_parser.py     # 21 проверка, полностью офлайн
```

На фикстурах из `tests/fixtures` (сняты один раз из кеша): разбор каталога,
разбор карточек со сверкой с эталоном, разбор цен/остатков/рейтингов,
нормализация, все проверки качества, выгрузка CSV и XLSX с обратным чтением
файла. Сеть в тестах не нужна вообще.

## Что бы улучшил для реального заказа

- Браузерный бэкенд с ротацией и человекоподобными паузами, если сайт
  защищается; селекторы — в конфиг, чтобы правка не требовала деплоя.
- Инкрементальный сбор: забирать только изменившиеся карточки по хешу содержимого.
- Схема ответа (pydantic) и валидация на входе парсера, а не только на выходе.
- Планировщик и доставка результата заказчику (почта / Telegram / Google Sheets).
